## Known limitations

- wger's "Trapezius" and longhaul-fitness' "trap" cover the whole trapezius; they map to the `traps` group (upper trapezius). On rows and rear-delt work the middle trapezius (`upper_back`) is meant, so `upper_back` is under-counted unless free-exercise-db ("middle back") or the pipeline table covers the exercise.
- No source tags hip flexors; neck work only comes from free-exercise-db.
- Records without equipment information stay separate from same-named exercises with equipment (review queue) instead of being guessed.

## How the build decides

- **Match key** = normalized name + load equipment. Names: lowercase, accents and punctuation stripped, abbreviations expanded (db, bb, kb, ez, rdl, ohp), synonyms and plurals unified, filler and equipment words dropped, tokens sorted (`taxonomy/name_rules.yaml`). Load equipment excludes accessories such as bench, mat and pull-up bar (`taxonomy/equipment.yaml`), because sources disagree on listing them; exercises with different load equipment are never merged. If a record has no equipment, it is taken from equipment words in its name; otherwise it stays unknown and only matches other unknowns.
- **Fuzzy matching**: rapidfuzz `token_set_ratio` between keys with the same load equipment. >= 95: merge, 85-94: review queue and separate exercise, below: new exercise. `token_set_ratio` is 100 whenever one name's tokens are a subset of the other's ("deadlift" vs "romanian deadlift"), so an auto-merge additionally requires that every differing token has a near-identical counterpart (a spelling variant). Names differing only by variation words (incline, seated, single-arm, ...) are separate exercises linked with `variation_of`; other extra words send the pair to the review queue. Records of the same source are only merged on an identical key.
- **Records that cannot create an exercise**: no English name, or no primary muscle. They can still attach to an exercise on an exact name match.
- **Muscle roles**: per source, the highest role it gives a muscle; across sources, the majority role, ties go to the higher role. `confidence` = sources agreeing on that role / sources with any muscle claim for the exercise. A group-level claim ("shoulders") counts as support for that group's specific muscles. A group row is dropped when a specific muscle of the same group is present, unless the group's role is higher.
- **Reviewed mappings**: `spottr-pipeline` (the vision pipeline's own exercise -> muscle table, `backend/vision/exercises.py`) attaches through `taxonomy/pipeline_labels.yaml` and its muscle list is final for the exercises it covers (`authoritative_sources` in `config.yaml`). Weights become roles: >= 0.8 primary, >= 0.4 secondary, else stabilizer. `confidence` still shows how many sources agree.
- **Movement pattern and laterality**: explicit token rules in `taxonomy/movement_rules.yaml`; NULL when no rule applies.
- **Instructions**: from the record with the most permissive license (then source priority), never from a disputed source, and only if the text looks English (stopword check).
- **Review queue reasons**: fuzzy score 85-94; extra words with token_sort_ratio >= 85; names differing only by a default-form word (bent-over, standing); same name where one side has no equipment; a match only through a source alias; a name whose equipment word contradicts the source's equipment.
- **IDs**: `taxonomy/id_registry.csv` keeps (source, record) -> exercise id forever; rebuilds reuse it and only add rows. To resolve a review-queue row, edit its registry row: set `exercise_id` to the candidate (merge) or keep it (separate), and set `match_method` to `manual`.
